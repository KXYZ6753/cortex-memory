## How confirm2.js's guards work

**`run <arm>` (TEST), in this order.** TEST data is read only after steps 1 and 2 pass.

1. **Pre-registration** (`preregStatus`; reads only git, the addendum and code files). Refuses unless all of these hold:
   - `benchmarks/premise2/PREREG-EXPLORE2.md` exists, is tracked, has a commit, and has no uncommitted changes.
   - It contains three machine-readable lines (the draft has them at the top):
     - `Arm: \`<arm>\``, equal to the arm requested;
     - `Verdict key prefix: \`X-explore2-…|small|<questionKey>\``, which becomes the cell id for grading;
     - `Code hash: \`<64 hex>\``, equal to `codeHash2()` now. The hash is sha256 over every file under `benchmarks/premise2/explore2/`, recursive, sorted, with CRLF normalised. It uses the same construction as `confirm.js codeHash()`. A `<fill at freeze>` placeholder refuses.
   - Nothing under `benchmarks/premise2/explore2/` is modified or untracked.
   - Every file of the arm's **import closure** is tracked and clean. The closure (84 files, found by following the static imports from confirm2.js, `registry.js`, every `variants/*.js`, the logger and the sampler) includes `explore/`, the frozen premise2 modules and `src/bm25.js`.
   - `explore/`'s code hash still equals addendum 3's registered `9801148b…`. It does today.
2. **Environment.** The checks below are enforced on a dry-run too.
   - The arm is an explore2 registry variant (`loadVariants`, the registry `cli2 run` uses).
   - Ollama's version and the e2b digest equal the main run's (`preflight`).
   - The default generation options (`generationOptions({ num_predict: 160 })`, what the arm was explored with) equal `run-state.json`'s provenance options exactly.
3. **TEST items.** Only now are the TEST items read: `confirmRecords(dataDir, 600)`, P-B items 0..599 in `agent-items.json` order. This is the same list as addendum 3.
4. **Under the GPU lock** (`withLock`, as `cli2 run`):
   - **Energy.** The runner starts the energy logger and the CPU sampler and verifies them before the model is loaded:
     - GPU samples are arriving;
     - CPU-package samples are arriving, and on TEST they must come from LibreHardwareMonitor;
     - its own pid appears in the sampler's process list.
     If any check fails within 25 s, it refuses.
   - **The run.** A fresh model load, two warm-up calls, a `ps` snapshot and a 30 s idle baseline, then blocks of 50 with an Ollama version check per block. The markers are in confirm.js's format.
   - **Stopping.** At the end the logger and sampler are stopped with `taskkill /T /F`, so nvidia-smi and the sampler's PowerShell do not outlive them.

**Store layout.** Output goes to `.data/premise2/explore/confirm2/`, which has `answers.jsonl`, `markers.jsonl` and `energy.jsonl` as in addendum 3, plus `cpu.jsonl` and `manifest.jsonl`.
- **`manifest.jsonl`** gets one `session-start` and one `session-end` record per invocation.
  - `session-start` holds:
    - git HEAD, the addendum's commit and sha256;
    - the explore2 code hash, the closure hash, and the explore/ hash against the registered one;
    - the runner, logger and sampler pids;
    - Ollama version, tag, digest and options;
    - the item-list hash and the pending count.
  - `session-end` holds the counts, statuses, mean wall time and an energy check: per-block integration, and the runner pid's CPU seconds from the sampler.
- **Answer keys:** `sha256(premise2-explore2-confirm-v1|mode|digest|arm@version|questionKey)`. They are resumable with ExploreStore's semantics: technical failures are retried up to 3 attempts.

**`--dry-run <devSet> [limit=5] [arm=q-det-q1]`** follows the same path with three differences:
- **Step 1 is evaluated, printed and stored** in the manifest (`preregOk`, `preregProblems`), but not enforced.
- **The set name is checked before anything is read.**
  - Refused: anything matching test / agent-items / pools / items / confirm / `.json` / a path, and anything that is not `S100-n`, `S300-n` or `FULL-n`.
  - Also refused: the round-5 reserved sets S300-4, S300-5, FULL-2 and FULL-3.
  - The set must then be in the exploration set registry, and every question must pass `explore/pool.js assertExplorable`: a tuning mailbox, and no TEST, retrieval or bridge email, twin or near-duplicate.
- **Output goes to `.data/premise2/explore/confirm2-dryrun/`** with cell `DRY-X-explore2-q1`, and LHM is preferred but not required.

`check <arm>` prints step 1's report and exits 1 if TEST would refuse. `hash` prints the code hash for the addendum.
