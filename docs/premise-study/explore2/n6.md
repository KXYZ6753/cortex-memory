# Worker n6 (round 6): document-contrastive decoding in multi-email contexts

Prefix `n6`. Code: `explore2/variants/n6-dcd.js`; offline tools `explore2/tools/n6-*.js`. Started Wed 7 Oct ~19:45 ET.

Question: CAD (u, round 5) is the only method that moved e2b's reading itself, and only for one email (gold-only hits +38/−24 over four dev sets). In five-email contexts it was null (u-gcad −0.1, u-xcad +0.3, u-xyc null). Does a **different contrast** rescue it in the contexts systems actually read?
- (a) **DCD**: contrast the full context C with C minus the evidence email E* (R1) or with E* replaced by a content-free filler of the same length (F1);
- (b) classic CAD on the full context with α tuned (u tried α 0.5 and AdaCAD only);
- (c) gated: only on unsure answers (greedy mean token logprob < τ).

## Summary (Thu 08 Oct 06:50 ET): a clean negative

Every arm runs behind det against det gates (`i-det-gates`); the greedy pass equals det gates’ answer on 6,849 of 6,850 paired dev hits (one FULL-1 re-roll), and questions where a gated arm did not fire are byte-identical, so every discordant pair is the decoder's. - **No contrast rescues CAD in five-email contexts.** Removing the evidence email (R1), replacing it by a filler (F1), the classic question-only contrast (Q) at α 0.25–1.0, gated or not, and a neutral-question contrast (QN) all land between −0.2 and +0.6 hit points on fresh hits. Nothing meets the bar (Δ ≥ +1.0, lower bound > 0); nothing went to H6-D, and nothing is a candidate for H6-C.
- **Why:** the decisions the contrast was built for (which name, number, date) are a coin flip under every contrast (§3: content changes +15/−16 for R1 α 0.5); the small net gains sit on wording rewrites and move between change classes from one set group to the next.
- **The contrast carries no information beyond a re-roll:** a content-free branch placebo on the same questions beat both contrastive decoders (+28/−13 vs +24/−19 and +25/−17), and then gave exactly 0 (+22/−22) on 1,050 unseen hits. Pooled over 2,350 hits the placebo is +0.64 [−0.13, 1.40], the same size as the contrastive arms.
- **Single-email CAD replicates behind det** (gold alone, 400 hits: +1.5 to +1.75 ungated, +15/−9 for α 0.5), but in context the effect is diluted to the re-roll level, and removing the evidence email as the contrast does not restore it.

## 1. Implementation

`n6-dcd.js`: speculative contrastive decoding (u's `cadDecode`, generalised to any contrast prompt), raw `/api/generate` with the template rendered by hand (u: `/api/chat` does not continue a prefilled assistant turn). Raw calls bypass det(), so the engine sends det's reset prompt (same tokens) before the first call of each prompt lineage (greedy C; each contrast prompt); all later calls continue the question's own cached prompts. β 0.1, ≤ 4 branches, top 20 (u's settings).

`n6-gx` (diagnostic, hits only): gates' contexts and abstention retry rebuilt (gatedMailbox is not exported); the official answer is the greedy raw pass, which should equal det gates' answer; one pass logs six configurations with memoised calls: R1 α 0.25 / 0.5 / 1.0, F1 α 0.5, classic CAD (Q) α 0.25 / 1.0. `n6-ox`: same on the gold email alone (R1 = classic CAD there).

## 5. A different contrast for fact decisions: the neutral-question contrast (QN) — fixed before running (Wed 23:28 ET)

Why: §3 shows that no document contrast moves the name/number/date decisions (coin flips), and the dominant hit error is a wrong fact or relation **from the right email** (j.md, u.md §0). Removing the evidence email lowers both candidate names alike when both come from it. A contrast that keeps the emails and removes the **question** separates what the context makes salient in general (the sender, the first name, the most frequent figure) from what this question asks for: QN = the same five emails with both question slots of the sandwich prompt replaced by "What do these emails say?". Score (1 + α) log p(y | C, q) − α log p(y | C, q_neutral).

`n6-gq` (diagnostic, hits only, behind det, batch runner `tools/n6-batch.js`): greedy = det gates; on unsure answers (τ −0.1) logs QN α 0.5 (**pre-registered primary**, same α and τ as the R1 candidate, nothing tuned), QN α 1.0 and QN α 0.5 restricted to content positions (secondary, descriptive). Evaluated on all 1,900 dev hits (S300-1..5, FULL-2, FULL-3) at once; bar as before.

`n6-g-r1g` validation flips by change type (454 changed answers on 1,300 hits): any content change +14/−9, wording only +10/−10. On the tuning sets (ungated R1 α 0.5) it was content +15/−16, wording +10/−5. Neither class is consistently positive: the small pooled gain moves between classes from one set group to the other.

## 8. Placebo for the gated decoders (`n6-g-pbo`, queued Thu 03:07 ET)

The two gated decoders change the same weak answers: on the 1,300 fresh hits, of the questions R1 fixed, 13 were also fixed by Q (and 12 Q fixes were not R1's); 7 breaks are shared (`tools/n6-overlap.js`). That pattern is what a content-free re-roll of unsure answers would also produce (n.md: any prompt change is a coin flip on unsure hits). Placebo: same gate (τ −0.1), same sites (β 0.1), same branching machinery and ≤ 4 branches, but no contrast: at each plausible position it branches with probability 0.25 to a hash-chosen non-greedy plausible token (≈ 2.5 branches per fired answer; R1 makes 2.0, Q 3.0). Same 1,300 fresh hits.

Is "branch an unsure answer at a plausible token" itself a real gain? Prompt-level re-rolls say no: on the same unsure hits (gates' greedy mean < −0.1, 505 questions), p6's same-token placebo `p6-eperm` is −1.19 (+12/−18) and `p6-e4` −0.99 (+23/−28); on sure hits both are ~0 (`tools/n6-reroll.js`). u's padding placebo on S300-4/5 unsure hits: +8/−6. The decode-level branch differs from a prompt re-roll (it keeps the greedy prefix up to a plausible position and changes one token there), but +28/−13 (sign test p ≈ 0.03) on one pre-specified run is also the size of a lucky draw.

## 10. Conclusions

1. **Bar not met; nothing for H6-D or H6-C.** Best contrastive arm on fresh dev hits: `n6-g-q1g` (classic CAD α 1.0 on unsure gates answers), +0.62 [−0.38, 1.62] hit points, +25/−17, 1,178 ms and 6.5 calls per question (det gates 764 ms, 2.0). The a priori document-contrastive arm `n6-g-r1g` is +0.38 [−0.62, 1.38]. H6-D was not used: no arm passed the development bar, and a branch placebo is as good as any contrast.
2. **Mechanism, measured:** at the positions DCD can change, the evidence-vs-distractor contrast does not know the right name/number/date (content decisions +15/−16; E1 = gold or not makes no difference). e2b's in-context errors are not distractor-driven token choices that a leave-one-out contrast can see; they are misreadings inside the right email (j.md, l.md), and the contrast distribution with the email removed is equally uninformative about both candidates.
3. **CAD on one email is real but small** (det, 400 hits: +1.5 to +1.75 hit points, mostly on confident answers); it does not transfer to five-email reading under any contrast tried.
4. **Cost if anyone revisits it:** speculative contrastive decoding through Ollama costs +400–900 ms and +4–9 raw calls per question gated at τ −0.1 (≈ 37–40% of hits fire); ungated about +900 ms. All well inside the 3,243 ms cap.
